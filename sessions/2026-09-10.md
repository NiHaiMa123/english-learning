## New language

1. `merge-ready` / `make a pull request merge-ready` — 达到可合并状态
   - `Resolve merge conflicts first to make the pull request merge-ready.`

2. `resolve review feedback` — 处理 / 解决评审反馈

3. `fix failed checks` — 修复失败的检查项

4. `resolve merge conflicts` — 解决合并冲突
   - preferred technical collocation over the learner's `solve the pull conflicts`.

5. `content exclusion(s)` — 内容排除

6. `sensitive code` / `sensitive files` — 敏感代码 / 敏感文件

7. `keep A out of B` — 不让 A 进入 B
   - `Keep sensitive files out of the agent's context.`

## Important contrast

### `prevent A from doing B`
Learner wrote:
- `content exclusions can prevent sensitive code from the agent's context`

Correction:
- `Content exclusions can prevent sensitive code from entering the agent's context.`

The pattern requires an action after `from`: `prevent A from doing B`.

### `keep A out of B`
After explanation, learner correctly produced:
- `these rules can keep sensitive flies out of the agent's context`

Only error:
- `flies` -> `files`

The final task later reverted to:
- `don't make sensitive files into the agent's context`

So the `keep A out of B` chunk still needs spaced review.

Preferred version:
- `Before merging the pull request, fix the failed checks, resolve review feedback, and then resolve the merge conflicts. Keep sensitive files out of the agent's context. The goal is to make the pull request merge-ready.`

Main issues:
- add a space after the comma,
- use `keep sensitive files out of ...` rather than `make sensitive files into ...`,
- `In order to make ...` was a sentence fragment; use `The goal is to make ...` or attach the purpose clause to a complete sentence.
