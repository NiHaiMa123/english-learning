## New language

1. `count toward ...` — 计入某项要求 / 计入总数
   - contrast: `count as ...` = 被算作 / 被视为某一项
   - learner initially guessed “代替”, then correctly produced `This approval can count toward one of the two required approvals.`

2. `dismissed` / `an approval is dismissed` — 被作废 / 失效
   - learner correctly recognized the meaning and later used the passive form in an integrated task.

3. `authorize A to do B` — 授权 A 做 B
   - initial attempt: `authorize this agent's sensitive actions`
   - after correction, learner correctly produced `authorize the agent to modify these files`.

4. `assess whether ...` — 评估 / 判断是否……
   - contrast introduced: `assess whether ...` vs `verify that ...`
   - `assess whether` is appropriate when the result is still uncertain;
   - `verify that` is used to confirm an expected claim/result.

5. `meet the acceptance criteria` — 满足验收标准
   - learner used the chunk correctly several times; one spelling error `critiria` -> `criteria` occurred.

6. `assume + clause` — 假设……
   - initial error: `assume this plan working`
   - later corrected to `Don't assume the new commit still works.`

7. `reassess whether ...` — 重新评估是否……
   - learner correctly reused this in the final integrated instruction.

8. `request a new review` — 请求新的评审
   - preferred over `make a new review`.

9. `feature` vs `function`
   - in product/software UI language, `feature` is often more natural for “功能”; this was a supporting correction rather than a main review item.

## Important corrections

- `even ... collision enabled` -> `even with collision enabled`
- `steel` -> `still`
- `make fewer penetrations` -> `reduce penetration`
- `self-collision enabled` -> `Enabling self-collision ...`
- `clip through itself` -> `intersect with itself` for cloth self-intersection
- `authorize this agent's sensitive actions` -> `authorize this agent to perform sensitive actions`
- `doesn't authorize` vs `hasn't authorized`: use present perfect when meaning “has not authorized up to now”
- `function` -> `feature` in the relevant software-product context
- `assume this plan working` -> `assume this plan works` / `assume this approach is feasible`
- `make a new review` -> `request a new review` / `a new review is required`
